ResumeOS

A personal resume intelligence platform — store your career story once, tailor it for any role, score your fit against any job description, and track every application in one place.

Built by Debjyoti Samanta · UW Foster MBA 2026 Solo-built using Claude Code + Claude API Local-first · No backend · Runs entirely in browser

The Problem

  • 1
    Applying across different functions and industries means the same experience needs to tell a different story per role — managing multiple resume versions manually is slow and inconsistent.
  • 2
    Without an objective score, candidates can't measure how well their resume matches a JD or know which edits actually move the needle.
  • 3
    Generic AI rewrites without knowing the real context behind bullets — producing polished but inaccurate text that fails the recruiter scan.
  • 4
    After applying to many roles, there's no closed loop — which version was sent, what was the score, and what happened to the application?

The Solution — Four Pillars

🗂️

Experience Repository

One source of truth · multiple bullet "lenses" per achievement · full project context stored

🎯

JD Analyzer & Scorer

Two-layer score — ATS keyword ranking + human recruiter evaluation — against any job description

✏️

AI Edit Engine

One AI call returns suggested edits with per-point impact · live score updates as you accept or decline

📋

Application Tracker

Every application logged with the exact resume version sent, score at time of applying, and outcome

D2 — Two-Layer Scoring Model
🔍 Layer 1 — Will you be FOUND? (ATS)
Keyword Match 35% Tier-weighted · placement multiplier
JD keywords tiered by importance:
Tier 1 · 3× — Job title terms Tier 2 · 2× — Required skills Tier 3 · 1× — Preferred / nice-to-have
Placement bonus: Summary (2×) · First bullet (1.5×) · Skills section (1×) · Deep bullets (0.8×)
👤 Layer 2 — Will you be SHORTLISTED? (Human)
Skills Alignment 25% Required 2× · Preferred 1×
Experience Relevance 15% Each bullet rated 1–5 for JD fit
Job Fit 15% Seniority · Function · Industry · Narrative
Format Compliance 10% 20+ ATS formatting checks · fully deterministic
Overall Score = 35% Keyword + 25% Skills + 15% Relevance + 15% Job Fit + 10% Format

D3 — AI Integration Design
🤖 Everything from a single AI call

Inputs

Job description · Uploaded resume text · Full experience repository with project context

→

Claude — one prompt

Scores resume · identifies gaps · generates suggested edits · projects post-edit score · writes cover letter

→

Outputs

Current score · projected score · per-edit point breakdown · job fit analysis · cover letter

Post-edit scoring — no second AI call

AI returns once

Current score: 52 · Projected score: 72 (if all edits accepted)

→

User accepts some edits

E.g. 3 of 5 accepted · combined impact = 60% of total possible

→

Deterministic interpolation

New score = 52 + (72−52) × 60% = 64. Math, not AI. Instant.

Why not re-run AI after each edit? A second AI call produces inconsistent scores — the model may change its assessment based on subtle prompt differences. Deterministic interpolation gives a score that is mathematically tied to the original analysis, transparent to the user (each edit shows its exact point contribution), and instant with no added API cost.
Two access modes
FREE MODE
Prompt is built and shown → user copies to Claude.ai → pastes response back. Zero API cost. Full functionality.
API MODE
Enter Anthropic API key in Settings. Same prompt fires automatically. One toggle — identical UX and output.

D5 — Key Product Decisions & Trade-offs
Architecture

Local-first · No backend

All data lives in the browser. No server, no database, no deployment pipeline.

✓ Chosen because
Zero setup · complete privacy · no recurring cost · works offline
✗ Trade-off
Single device only · no sync · ~5MB storage ceiling
AI Design

Single AI call + deterministic re-score

One prompt returns current score, projected score, and all edits. Post-edit scoring is pure interpolation.

✓ Chosen because
No circular loop · consistent results · transparent · no added API cost
✗ Trade-off
Projected score is an estimate — not a fresh AI opinion after accepting edits
Data Model

Multi-lens bullet variants in repository

Same achievement stored with separate bullet text per target function, not as a single generic bullet.

✓ Chosen because
Instant tailoring without AI · preserves nuance · no hallucinated rewrites
✗ Trade-off
Higher upfront effort to populate the repository with all variants
UX

Analyzer-first, not Generator-first

Primary flow: paste JD → upload PDF → score → edit. Resume generation from scratch is secondary.

✓ Chosen because
Matches real behavior — you have a resume, you need to optimize it for a specific role
✗ Trade-off
Resume generator is underutilized as a standalone starting-from-zero feature
